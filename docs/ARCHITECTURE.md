# 合合部落：当前工程结构

项目使用 Godot 4.6.3，当前只有一套玩法规则和一种存档结构。客户端、自动玩家与服务端校验调用相同的 reducer。未上线阶段不保留旧版游戏接口、旧存档迁移或模拟支付流程。

## 模块职责

| 层 | 文件或目录 | 职责 |
| --- | --- | --- |
| 玩法入口与状态 | `scripts/Game.gd` | 当前状态、带日志的命令入口、语义展示事件；查询直接访问 `G.rules` |
| 领域规则 | `scripts/domain/` | `RuleContext` 注入实例状态、时钟、随机流及副作用；棋盘、订单、成长、商店与时钟服务直接互调；严格快照编解码 |
| 活动规则 | `scripts/events/` | `ActivityRules` 注册初始化、时间推进、订单结算与入口开放条件；不执行网络请求或绘制 |
| 命令执行 | `scripts/replay/Reducer.gd`、`Replay.gd` | 确定性输入、时间推进、失败回滚、按变化域通知 |
| 本地持久化 | `scripts/replay/Journal.gd` | 追加并刷盘的操作日志、原子完整检查点、重启恢复 |
| 资源 | `scripts/resources/`、`ItemAnim.gd`、`Sprites.gd` | 按需加载、按像素字节数限制缓存、无渲染环境跳过资源 |
| 展示 | `scripts/ui/`、`scripts/Main.gd` | 订单卡复用、弹窗栈、配置编辑器、动画与音效 |
| 配置 | `scripts/config/`、`Data.gd` | 只读缓存、可编辑副本、整套校验、批量提交、版本失效 |
| 网络 | `scripts/net/Cloud.gd` | 账号与压缩操作批次传输，不执行玩法结算 |
| 服务端 | `server/app/` | 身份、有限 worker 池、确认存档、幂等与短事务提交 |

`Rewards.settle()` 只结算业务数据；`RewardPresenter.present()` 只展示已结算结果。打开、关闭或中断奖励动画不会改变奖励到账次数。规则层通过 `G.present()` 排队展示意图，命令落盘成功后才分发。

`ActivityRules.initialize()` 在规则执行期间初始化活动状态；界面读取活动状态不会推进随机流或偷偷修改存档。

## 输入、日志与同步

客户端有效输入在执行前后取得业务快照，后快照复用未变化的独立分支；所有快照都与可变的现场状态隔离。服务端仅为回滚保留前快照，非 tick 命令不建立后快照、不计算逐条哈希，批次结束统一计算最终哈希。业务快照从构造时就不包含操作队列、设置和本机展示记录；业务数值原地规范化，不再通过 JSON 往返重载整份游戏。

命令成功后，操作与结果摘要先追加日志并刷盘，再通知界面。每 32 条输入、最长约 5 秒，以及同步确认或退出时写完整检查点。检查点带独立 generation；旧日志、截断的末尾记录和未确认批次不会被重复结算。写盘失败会撤销操作。非法输入不生效，期间合法的计时变化可以单独记录为 tick。

每分钟最多启动一次自动同步，每批最多 256 条输入。客户端只上传压缩操作和结果哈希。服务端通过常驻 Godot worker 重放，从确认点生成新状态；事务外执行耗时校验，提交时重新检查会话、存档版本和批次内容，原子更新确认点。

当前规则指纹由纯规则命名空间和依赖图自动生成。UI、资源缓存、网络编码与 worker 服务协议不属于玩法规则。只接受当前规则版本，不运行旧规则程序。

卡册手动领奖使用追加的 `album_claim` 命令，不改变已有线协议操作码。旧版自动发奖标记沿用为已领取标记。针对该次更新的指定离线规则指纹，先按原奖励语义恢复尚未写检查点的日志，再原子保存到手动领奖版本；保留卡片、资产、玩家身份及已领取记录。其他未知规则版本仍按原规则版本检查处理。

## 界面与资源

卡册封面从 `assets/cards/covers/album.json` 读取，每个集合拥有独立图片，并以圆形绘制。封面与卡片插画均属于展示资源。领奖界面只消费已提交的奖励结果，通过 `RewardPresenter` 复用飞行动画，不在动画回调中再次修改资产。

订单交付界面只消费成功提交的命令结果，包括实际奖励、角色与台词；落盘失败时不会播放成功动画。订单条按稳定订单标识维护卡片。棋盘、订单通知在同一帧合并处理，只更新变化数据或顺序，未变订单保留节点和动画。隐藏界面与滚出裁剪区的控件暂停手绘沸腾订阅。主界面和棋盘切页会暂停整个展示子树，隐藏时合并积累刷新，返回时更新一次；规则时间仍由 Replay 推进。村庄木牌按建筑 ID 复用。棋盘按格保留绘制，制作、提示和气泡只连续重画相关格子；生成器文字按秒更新，提示搜索仅在局面变化后重新计算。

`ActivityEntries` 只负责活动 ID 到视图的映射；`BoardActivityRow` 接收明确控件绑定，按注册顺序布局，不访问 BoardScreen 私有字段。

`StateValues` 为存档恢复、现场规范化与哈希快照提供同一种数值表示。`AtomicFile` 是检查点原子写入的唯一实现；Journal 继续在命令提交前追加并刷盘。

物品帧缓存上限为 64 MiB，界面图为 48 MiB，活动图为 16 MiB。图片仅在实际绘制当前帧时加载。服务端和 headless 工具不初始化图片、音乐或音效。

配置编辑器首次打开才创建，页面按功能拆分。保存前校验整个候选配置，并事务写入文件；成功后刷新缓存并重开测试局。联网模式不允许改规则，保存失败会原样还原配置与运行状态，操作日志不会跨规则混用。

## 验证与导出

```sh
python tools/check_project.py --godot /path/to/godot --python /path/to/server/python
python tools/export_web.py /path/to/godot
```

完整检查覆盖配置、规则指纹、源图片完整性与缓存、领域规则、奖励展示、数值资源、追加日志与真实重启、UI 节点复用、实际 Godot/HTTP 重放和服务端事务。缺少 Godot、运行错误或跳过服务端检查均视为未通过。

浏览器发布保持静态试玩：使用 `--cloud-off`，执行相同 reducer，存档留在浏览器。账号同步后端单独运行，部署与容量配置见 `server/README.md`。不把静态试玩描述为已部署联网服务。

`scripts/art` 保留运行时矢量后备图及烘焙共用画法；`scripts/preview` 只保留开发预览页面。发布排除开发截图、预览场景、烘焙脚本、编辑插件和服务端 worker。导出验证依据实际预设构建清单，并在空目录加载真实 PCK，检查全部运行脚本、物品帧和被排除资源。

## 可复现的重放基准

```sh
godot --headless --path . --script tools/benchmark_replay.gd -- --replay-worker --cloud-off --save=/tmp/tribe-benchmark.json
```

基准使用 30 级活动状态，交替执行 1,024 次 boost 命令，预热一轮后取五轮中位数。本次同机对比 `8ffa1e3`：每条操作由 1,392.8 µs 降至 725.8 µs（减少 47.9%）；两版最终业务状态 SHA-256 完全一致。该结果衡量固定场景的服务端重放，不代表手机帧率或所有操作的提升比例。

# 统一价值与区域定价

唯一商业策略配置：`server/config/economy.json`。`server/app/economy.py` 将策略和实际产线、配方、宝箱掉落配置编译成带版本号的最终目录。客户端 `PriceBook` 读取服务端给出的物品分数和最终价格，不再用热卖、礼包各自的估价系数。

## 本版锚点

- 1体力 = 1价值分，1琥珀（钻石）= 1价值分，1不那那 = 0.2价值分。
- 每份沙漏仍加速6秒，1小时对应600份，整包价格6琥珀。
- 主产物5/7/8级价格为16/50/97琥珀；3级副产物22琥珀；1级生产器120琥珀。
- 基础获取分与商店价格分开保存。订单使用 `difficulty`；热卖使用服务端给出的 `amber` 价格，合成泡泡保留独立折扣渠道，读取服务端给出的 `bubble` 价格。
- 当日每次购买100体力，价格依次10、20、40、80、80……；按现有服务器UTC+8换日规则重置。首次引导免费补充仍独立保留，不占付费次数。
- CN与US物品基础分一致；现金价格、充值数量、币种和格式分别配置。US美元小数价格完整保留，通行证升级显示服务端计算的差价。

## 目录与支付

`GET /v1/economy/catalog` 返回服务端市场对应的目录，市场由 `TRIBE_PRICING_MARKET=CN|US` 决定，付费请求里的市场、价格和数量不能覆盖服务端配置。内容包括：

- `items`：每个物品的基础分、定向难度、琥珀价、不那那价、产线和生产器碎片当量。
- `products`：付费商品最终价格、币种显示和内容分数。
- `documents`：运行时覆盖旧作者配置的商业数值及奖励配置。
- `resource_products`：可购买的不那那与各时长沙漏。
- `reward_audit`：活动奖池预算、预算调整前后的分数和生产器碎片当量。

`POST /v1/economy/purchases` 支持体力、沙漏、不那那及当前热卖商品。客户端提交商品编号、目录版本和已展示价格；服务端用当前目录重新核价。服务器按账号事务锁、幂等键和已保存钱包处理，尚未送达的权益先预留消耗，避免并发超支。购买结果沿用现有 `Grant` 投递：客户端一次性扣除已核准的琥珀、发放内容并上传，重复回复不重复扣款和发货。

体力次数以服务器购买记录为准，并兼容本日旧存档已有次数。版本或已展示价格变化时拒绝旧报价，余额不足不消耗次数。真钱商品继续使用原工程的支付订单与凭证校验流程；本版增加区域报价，没有新增真实支付SDK。

## 奖励与定向难度

普通物品按合成材料当量计算；副产物用已有生产器配置的参考掉率计算定向难度；制作物品累加材料分与独立加工时间。随机卡包使用配置的参考新卡率、各星级新卡值和重复转星规则计算规划期望值。资源宝箱按真实掉落概率和保底计算期望值；生产器碎片当量另记。

活动配置仍是奖励内容的作者输入，服务端按奖池预算缩放数量，并单独限制生产器当量，生成最终奖励列表。客户端显示和结算都使用同一份最终列表。预算是每次完整活动配置/周期的预算，不表示账号终身奖励上限；已有付费权益按购买时保存的内容投递。

## 客户端和试玩

原生客户端启动时请求后端目录，并缓存最后一次成功响应；价格未准备好时关闭商业购买。配置更新通过新的操作日志周期切换，保留玩家进度。市场切换使用相同玩法指纹，避免仅更换现金币种就重置存档。

网页试玩沿用原工程的 `--cloud-off` 本地存档模式。构建通过 `tools/compile_economy.py` 从同一份服务端策略生成CN/US公开快照，单独发布为 `economy-cn.json`、`economy-us.json`；网页先获取快照，再启动游戏引擎。开发检查可用 `?market=US` 查看美元配置。试玩不启用真钱模拟扣款，正式联网购买走上述后端接口。

修改服务端策略后运行 `python tools/compile_economy.py`；Web导出也会自动执行。`data` 下旧文件中的历史现金字段用于旧作者格式兼容，运行时商业价格由服务端投影覆盖。价格策略不再从客户端配置编辑器的体力价格项保存。

## 检查

- `server/tests/test_economy.py`：区域报价、忽略客户端伪造价格、阶梯封顶、每日重置、余额预留、幂等及版本冲突。
- `tools/check_economy.gd`：客户端价格锚点、失败不涨价、换日、沙漏实际秒数和权益只结算一次。
- 保留原支付、云存档、订单节奏、生产器成长和热卖规则检查。

# 活动棋盘与自选宝箱配置

客户端与 Python 服务端共用 `data/merge_events.json`。当前活动「月石遗迹」10 级开放，每周一期；香蕉竞速独立使用 `server/config/race.json`，12 级开放，仅前三名按名次递减奖励。

## 开设新一期

`seasons` 按顺序选择第一项处于时间窗口且启用的活动；同一时间只显示一套活动棋盘。每个配置可以按 `repeat_days` 自动重复，存档以 `id:期数` 隔离，积分、棋盘、发现与领奖状态不跨期继承。

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一小写字母/数字/下划线标识；修改产线或棋盘尺寸必须使用新 ID，不能覆盖旧存档结构 |
| `title` / `entry_title` | 面板标题与任务栏入口文字 |
| `enabled` / `unlock_level` | 是否开放、玩家等级门槛 |
| `start_utc` | UTC 起始时间，格式 `2026-11-02T00:00:00` |
| `duration_days` / `repeat_days` | 每期持续天数、重复间隔；间隔为 0 表示只开一期；持续时长不超过重复间隔 |
| `chain` | 由低到高的物品数组，每项包含独立 `id`、`name`、`icon` 资源路径；至少两级 |
| `theme` | `background` 面板主色，`panel` 奖励卡片底色，`tile`/`tile_alt` 地板色，`locked` 锁定格色，`accent` 积分气泡色，`point_icon` 积分图标路径 |
| `rewards` | `[[主棋盘物品ID, 数量], ...]`；资源数量是实际到账量，其余物品进入暂存区；通过统一领奖函数结算 |

保留旧期配置以支持查看旧棋盘及领取已完成的奖励。过期后不能投放、合并或回收，但已完成且未领取的奖励仍可领取一次。更换美术可直接替换图标路径；美术必须随 Godot 工程导出。

## 棋盘与积分

`board.cols`、`visible_rows`、`total_rows` 设置列数、可见行数、总行数。建议保持当前 6 列、可见 7 行；总行数必须不小于可见行数。`reveal_rows` 必须是正整数，不超过可见行数。固定显示区域为 576×672，格子尺寸自动适配。

除最底下一排为空格外，其他格子初始完全覆盖（lock=2），不显示物品身份。`locked_tiers` 是锁定物品等级的循环分布，`seed` 控制分布偏移；最下面两行锁定物品固定为一级，确保能开始合并。锁定等级应在 1 到产线倒数第二级之间。

在上下左右相邻位置完成合成，可把完全覆盖格变为显示但锁定（lock=1）；再把同级物品合并进去解锁（lock=0）。覆盖格不能直接合并。与主棋盘共用相邻格揭露逻辑。旧存档保留已有进度，并迁移未揭露格。

当前最上方整行解锁后，棋盘自动下滑，最多展示 `reveal_rows` 行。即将移出视野的物品搬到新视野内的空格；空间不足时减少滚动行数或等待继续合并，不丢失物品或留下不可达锁定格。移除手动上下翻页、滚轮导航和往期/回收入口。通关奖励及领取按钮位于棋盘上方。普通物品允许交换位置。

`board.goal` 为 `unlock_all` 时，解锁全部格子领奖；为 `discover_all` 时，发现全部产线等级领奖。

`points.order_thresholds` 为升序难度阈值，`order_rewards` 比阈值多一项，奖励限制在 1–3 积分。难度 = 订单中最高物品等级 + 物品数量 - 1。当前阈值 `[4,8]`，对应奖励 `[1,2,3]`。只有达到开放等级后完成主棋盘订单才获积分。

`spawn_cost` 为每次投放的正整数积分，`spawn_tier` 为产线中的有效等级（当前均为 1）。满盘或失败不扣积分。活动没有生产器，产物不能进入主棋盘。

## 自选宝箱

`data/chains.json` 注册 `type: "choice"` 的主棋盘物品；`data/choice_chests.json` 为每个宝箱 ID 配置 `title`、`icon` 和恰好三个有效主棋盘物品 ID 的 `choices`。

当前 `choice_1` 可在 `fire_4`、`shell_4`、`amber_3` 中三选一。宝箱必须先放到棋盘，点击后打开面板；关闭保留箱子，确认后原格替换，即使满盘也可选择。资源类产物保持可合并实物，不直接兑换到资源栏。服务端以每种宝箱独立的领取额度限制重复开箱。

## 代码与验证

- `scripts/merge/MergeGrid.gd`：主棋盘与活动共用格子定位、邻居、最近空位、拖拽判定及交换/合并基础修改。
- `scripts/events/MergeEvent.gd`：活动配置、进度、动作、领奖与服务端调用。
- `server/app/merge_event.py`：联机活动的积分、动作与奖励权威校验；上传快照不能覆盖活动进度。
- `tools/check_merge_event.gd`：等级、积分、合并解锁、滚动、保存、一次领奖、宝箱与 UI 检查。
- `server/tests/test_merge_event.py`、`server/tests/test_race.py`：接口与竞速奖励回归。
- `tools/export_web.py`：导出后从实际包验证活动、宝箱与原有物品图片。

网页发布使用独立本地存档模式。月石遗迹和自选宝箱支持该模式；香蕉竞速支持本地模拟对手及独立匹配面板。真实联机仍需 Python 服务端，服务端代码修改不会随静态网页自动部署。

# 活动棋盘与自选宝箱配置

客户端与 Python 服务端共用 `data/merge_events.json`。当前活动「月石遗迹」10 级开放，每周一期；香蕉竞速独立使用 `server/config/race.json`，12 级开放，仅前三名按名次递减奖励。

## 开设新一期

`seasons` 按顺序选择第一项处于时间窗口且启用的活动；同一时间只显示一套活动棋盘。每个配置可以按 `repeat_days` 自动重复，存档以 `id:期数` 隔离，积分、棋盘、发现与领奖状态不跨期继承。

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一小写字母/数字/下划线标识；修改产线或棋盘尺寸必须使用新 ID，不能覆盖旧存档结构 |
| `title` / `entry_title` | 面板标题与任务栏入口文字 |
| `enabled` / `unlock_level` | 是否开放、玩家等级门槛 |
| `start_utc` | UTC 起始时间，格式 `2026-11-02T00:00:00` |
| `duration_days` / `repeat_days` | 每期持续天数、重复间隔；间隔为 0 表示只开一期；持续时长不超过重复间隔 |
| `chain` | 由低到高的物品数组，每项包含独立 `id`、`name`、`icon` 资源路径；至少两级 |
| `theme` | `banner` 标题横幅色；`sky_top`/`sky_bottom` 月夜背景渐变；`tile`/`tile_alt` 开放格砂岩色；`recess` 显示但锁定的石槽色；`covered`/`covered_alt` 覆盖石板色；`vine` 藤蔓色；`glow` 月光描边；`accent` 进度条与积分气泡色；`point_icon` 积分图标路径 |
| `milestones` | `[{at, rewards}, ...]`，按 `at`（解锁格数；`discover_all` 时为发现件数）升序，最后一项必须等于总目标，即通关奖励。`rewards` 为 `[[主棋盘物品ID, 数量], ...]`：资源数量是实际到账量，其余物品进入暂存区，经统一领奖函数结算。旧配置只写 `rewards` 时视为唯一一个通关里程碑 |

保留旧期配置以支持查看旧棋盘及领取已完成的奖励。过期后不能投放、合并或回收，但已完成且未领取的奖励仍可领取一次。更换美术可直接替换图标路径；美术必须随 Godot 工程导出。

## 棋盘与积分

`board.cols`、`visible_rows`、`total_rows` 设置列数、可见行数、总行数。建议保持当前 6 列、可见 7 行、总 16 行（90 个覆盖格 + 底排 6 个空格）；总行数必须不小于可见行数。`reveal_rows` 必须是正整数，不超过可见行数。固定显示区域为 576×672，格子尺寸自动适配。

### 三种格子

| 状态 | lock | 画法 | 规则 |
| --- | --- | --- | --- |
| 覆盖 | 2 | 凸起的月纹石板，爬着藤蔓，看不到物品；挨着开放格的石板描一圈月光，提示「在旁边合成能揭开」 | 上下左右相邻处完成一次合成就揭开（变为 lock=1；底下没物品则直接 lock=0）。不能直接合并 |
| 显示但锁定 | 1 | 凹陷暗石槽，物品冷色半透明，两角缠藤蔓 + 月牙石锁；拿着同名物品时发绿光 | 拖入同名物品合并后解锁（lock=0），得到下一级物品，并揭开它周围的石板 |
| 开放 | 0 | 暖色砂岩地砖，物品全彩 | 普通合并、移动、交换 |

### 难度分层

`board.layers` 自底向上分层：`[{rows, tiers}, ...]`，每层 `rows` 行，格子的锁定物品等级从 `tiers` 中按固定整数哈希取（`(深度×131 + 列×71 + seed×17) % 97 % len`，客户端与服务端同式）。越深（越靠上）等级越高，最后揭开的一层最难、也最值钱。最下两行应全为 1 级，保证一开始就能合。超出各层总行数的部分沿用最后一层。没有 `layers` 的旧配置继续使用 `locked_tiers` 的旧算法。锁定等级应在 1 到产线倒数第二级之间。

当前分层（深度从底排上方一行算起）：2 行全 1 级；4 行 `[1,1,1,2,2]`；4 行 `[1,2,2,2,3]`；5 行 `[2,2,3,3,4]`。

### 自动下滑

首次合成到指定遗物等级后，按 `board.advance_by_tier` 累计获得推进额度。当前 4、5、6 级分别推进 3 行（每行 6 格，共 18 格）；最高等级达到 6 级时总额度为 9 行。再次合出同级遗物不重复推进。单次搬移最多 `reveal_rows` 行，不要求视野最上方整行解锁。即将移出视野的物品搬到新视野内的空格；新视野搬移后至少留两个空格用于放置并合成一对碎片；空间不足时减少滚动行数或等待继续合并，不丢失物品或留下不可达锁定格。未用完的推进额度保留，每次放置、合成、移动或回收后重新检查；旧存档保留已经推进的位置，不后退。移除手动上下翻页、滚轮导航和往期/回收入口。普通物品允许交换位置。

`board.goal` 为 `unlock_all` 时，进度 = 已解锁格数 / 90；为 `discover_all` 时，进度 = 已发现产线等级数。

### 积分

`points.order_thresholds` 为升序难度阈值，`order_rewards` 比阈值多一项，奖励限制在 1–3 积分。难度 = 订单中最高物品等级 + 物品数量 - 1。当前阈值 `[5,8]`，对应奖励 `[1,2,3]`：抽样 10–20 级的随机单，约 25% 得 1 分、50% 得 2 分、25% 得 3 分，剧情单多为 2–3 分，平均约 2 分/单。只有达到开放等级后完成主棋盘订单才获积分。

`spawn_cost` 为每次投放的正整数积分（当前 1：1 积分 = 1 块月石碎片），`spawn_tier` 为产线中的有效等级（当前 1）。满盘或失败不扣积分。活动没有生产器，产物不能进入主棋盘。

### 节奏与奖励（一期 7 天）

- 订单量：按 `DESIGN.md` 节奏目标与 `tools/balance_out.json`，11–20 级每天约 540 下点击（450 自然 + 升级火种），其中约 3 张剧情单 + 4–5 张随机/制作单，活跃玩家约 7–8 单/天 ≈ 15 积分/天；重度玩家可到 25 积分/天以上。
- 旧版按清行推进的清盘成本参考（当前等级推进需重新评估）：用服务端规则跑贪心机器人（优先解锁、再合成、最后投放），当前配置清完 90 格约需 75 积分（不同 seed 75–81）；真人有零头浪费，估计 85–100 积分。旧配置（单层 `[1,1,1,2,2,3]`）只要 53 积分，2–3 天就清完，偏快。
- 旧版节奏估计：活跃玩家第 5–6 天通关，重度玩家 3–4 天，轻度玩家（约 4 单/天）一周能拿到前 2–3 个宝箱。机器人约在 17/33/50 积分时达到 15/35/60 格。
- 里程碑：

| 解锁格数 | 奖励 | 用意 |
| --- | --- | --- |
| 15 | 50 体力、藤编宝箱 | 第一天就能拿到，教会玩法 |
| 35 | 15 琥珀、兽皮卡包 | 第 2–3 天 |
| 60 | 25 琥珀、体力宝箱、藤编宝箱 | 第 4 天前后 |
| 90（通关） | 60 琥珀、150 体力、自选宝箱、兽皮卡包 | 一周的大奖 |

全程合计 100 琥珀 + 200 体力 + 体力宝箱 + 2 宝箱 + 2 卡包 + 自选宝箱。参照：买 100 体力 20–60 琥珀，香蕉竞速第 1 名（约 4 小时）20 琥珀 + 80 体力 + 卡包；一周活动约为 5 局竞速冠军的价值。

### 领奖

到达里程碑后，进度条上的宝箱节点跳动并显示「领取」，点一下领取**所有**已到达未领的宝箱（动作 `claim`，一次结算）。存档 `got` 记已领的里程碑下标；`claimed` 仍表示通关奖励已领（之后棋盘冻结）。旧存档 `claimed=true` 且无 `got` 视为全部已领。中途宝箱不冻结棋盘；过期后已达到的宝箱仍可领取。未到达的节点点开是奖励预览。

### 面板布局

顶部：剩余时间；石板进度条（`遗迹探索 x/90`，节点上显示宝箱/卡包/体力宝箱/自选宝箱）。中部：棋盘（石框 + 角落藤蔓）。底部：8 格遗物陈列（未发现显示剪影，点开看名称）；下方仅保留居中的放置按钮（显示月石碎片和剩余放置次数，有积分时呼吸）。动效：投放的碎片从气泡划弧飞入、合成闪光、解锁落叶 +「解锁！」、揭开时石板掀起碎裂、自动下滑后提示「更深的遗迹露出来了」、合出新等级弹「新遗物」横幅。

## 自选宝箱

`data/chains.json` 注册 `type: "choice"` 的主棋盘物品；`data/choice_chests.json` 为每个宝箱 ID 配置 `title`、`icon` 和恰好三个有效主棋盘物品 ID 的 `choices`。

当前 `choice_1` 可在 `fire_4`、`shell_4`、`amber_3` 中三选一。宝箱必须先放到棋盘，点击后打开面板；关闭保留箱子，确认后原格替换，即使满盘也可选择。资源类产物保持可合并实物，不直接兑换到资源栏。服务端以每种宝箱独立的领取额度限制重复开箱。

## 代码与验证

- `scripts/merge/MergeGrid.gd`：主棋盘与活动共用格子定位、邻居、最近空位、拖拽判定及交换/合并基础修改。
- `scripts/events/MergeEvent.gd`：活动配置、进度、动作、领奖与服务端调用。
- `server/app/merge_event.py`：联机活动的积分、动作与奖励权威校验；上传快照不能覆盖活动进度。
- `tools/check_merge_event.gd`：等级、积分、分层、合并解锁、滚动、保存、里程碑分段领奖与一次性、宝箱与 UI 检查。
- `assets/events/moon/relic_1..8.svg`、`point.svg`：月石碎片 → 月石吊坠 → 青铜月盘 → 月纹玉环 → 月辉王冠 → 月光权杖 → 月神雕像 → 月神祭坛，越高级越大、6 级起带月光光晕。覆盖石板、藤蔓与地砖提前烘焙为图集，`MergeEventBoard.gd` 只在状态改变时重绘，合并等动效单独绘制。
- `server/tests/test_merge_event.py`、`server/tests/test_race.py`：接口与竞速奖励回归。
- `tools/export_web.py`：导出后从实际包验证活动、宝箱与原有物品图片。

网页发布使用独立本地存档模式。月石遗迹和自选宝箱支持该模式；香蕉竞速支持本地模拟对手及独立匹配面板。真实联机仍需 Python 服务端，服务端代码修改不会随静态网页自动部署。

## 双人竞速

`data/duel_race.json` 独立设置解锁等级、目标香蕉数、订单积分与胜负奖励。面板从上到下为胜负奖励、两列香蕉堆、角色、比赛按钮、累计胜场进度条。订单积分表现为堆积的香蕉，先达到目标者获胜。

累计胜场条按配置的胜场数比例放置宝箱（当前 2、5、8、12 胜）。点击只展开小气泡预览，达到条件后在气泡内点击「领取」；已领宝箱可以再看内容，未达标时显示还差几场。点击空白关闭，比赛分数刷新不会收起预览。领奖继续使用本地或服务端统一结算及一次性校验。

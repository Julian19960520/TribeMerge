# 自动玩家与演算时间轴

直接在 Godot 里调用 `Game`、`Rewards`、合成棋盘和活动控制器；不复制一套 Python 经济规则。不连接线上账号，不改玩家存档，不修改机器时间。

## 运行

需要 Godot 4.6.3 与 Python 3，首次打开工程需完成 Godot 资源导入。

Windows 可双击工程根目录的 `自动演算.bat`，默认沿用 `运行游戏.bat` 的 Godot 路径；
也可设置环境变量 `GODOT_BIN`。命令行运行 `自动演算.bat --forever` 会持续循环。

```bash
python tools/sim/run.py --godot /path/to/godot --runs 1 --days 7 --publish-report
python tools/sim/run.py --godot /path/to/godot --forever
```

默认每次只运行 1 轮，达到 40 级即停止，不再继续跑到时长上限。`--forever` 会在每轮结束后不断从初始棋盘重开，种子递增；Ctrl+C 停止。每批结果独立保存到 `tools/sim/results/batch-*/`。完成的轮次以及当前批的 JSONL 已执行动作日志都保留。配置默认 `tools/sim/config.json`，也可用 `--config` 指向另一份。

| 配置 | 含义 |
| --- | --- |
| seed / runs | 初始随机种子 / 每批轮数 |
| cycle_days / max_actions | 每轮游戏内时长 / 动作安全上限，任一达到即结束重开 |
| action_seconds | 每个决策动作占用的游戏内秒数，当前为 2 秒 |
| start_utc | 每轮相同的起始时间，决定跨日及活动期次 |
| main_story_max_level | 0 自动取 story.json 的最后配置等级；完成后只做副线 |
| story_first | 优先可生产的主线；保护其材料，避免被副线抢用 |
| play_events | 参与月石、香蕉和双人竞速 |
| use_storage | 满盘时优先保留高价值闲置物品到储物洞 |
| expand_storage / max_storage | 是否允许花已有琥珀扩容 / 容量上限 |
| delete_max_level | 只丢弃不属于当前目标产线、等级不超过此值的普通物品，按生产成本从低到高选择；默认 10，生产器始终保留 |
| wait_energy_batch | 没体力时计划恢复多少点再继续；更近的计时事件可提前唤醒 |
| stop_level | 默认 40，达到后立即结束本轮；大于 0 时为等级终点 |
| schedule.days | 每天的在线时段，北京时间 `["HH:MM", 分钟]`；第 N 天用第 N 项，超出后一直用最后一项。不配 schedule 就是 24 小时连续在线 |
| schedule.quit_idle_minutes | 在线时没事可做、需要空等超过这么久（或等到时段结束），就记一次「卡住」并下线到下一段 |

## 产物

- `report.json`：配置、全部事件、轮次汇总及 data/*.json 的 SHA-256。
- `levels.md`：按等级汇总表（第几天升到、累计/本级在线时长、订单与经验单、生产与体力收支按来源、自然恢复、满体力浪费、卡住/卡体力次数、本级新解锁内容）及按天汇总；也可 `python tools/sim/levels.py report.json` 单独生成。数据来自 `report.json` 的 `runs[].levels`。
- `report.jsonl`：逐条写入的完整动作流水，意外中断也能查看已执行动作。
- `report-runN-save.json`：每轮结束时的独立状态快照。
- `simulation.html` + `simulation-report.json.gz`：可视时间轴。用任意静态服务器打开目录，或打开已发布的 `/simulation.html`。页面仅保留时间线／资源进度区和事件详情区，支持缩放平移、点选事件、指标切换和下载记录；多轮报告才显示轮次选择。订单、升级部落使用独立轨道，领奖按来源分轨显示；新记录用 `reward_source` 标记来源，旧记录自动兼容。
- 一键查看：双击 `tools/sim/view.bat`（或 `python tools/sim/view.py [批次目录|report.json]`），默认打开 `tools/sim/results` 里最新跑完的一批，没有就打开 `web/` 里的；也可以把批次目录或 report.json 拖到 view.bat 上。
- `--publish-report` 把报告放到 `web/`，随后常规 `tools/export_web.py` 自动带入发布包。

## 页面下载

“下载精简记录”生成带 2 空格缩进和换行的 `TribeMerge-timeline.json`，按轮次分组，仅包含：

- 各时间线以时间为属性名，值为简要文字，例如 `"1分": "篝火广场"`；不导出逐次合成、生产动作，保留独立的藤蔓解锁记录，不受页面当前筛选、缩放或动作显示模式影响。
- “资源与进度”各指标使用 `"时间": 数值`，不导出棋盘空格变化；保留初始值，只在数值变化时新增记录，相同时间保留全部动作完成后的最终数值，相邻时间数值不变不再重复输出。生产、合成引起的体力及生产器成长等数值变化仍保留。时间为距该轮开始的累计时长，页面和导出统一使用 `x小时x分x秒`，例如 `2小时15分8秒`；省略开头的零值单位，`0小时2分8秒` 显示为 `2分8秒`，`0小时0分8秒` 显示为 `8秒`，零时刻显示为 `0秒`。超过 24 小时继续累计小时，秒的小数部分按原记录精度保留。

下载不含完整状态快照、变化量字典、原因、原始动作详情、配置或文件哈希。订单简述区分有无经验；分类内去掉重复的“升级部落 · ”等前缀。同一时间的多条文字用分号合并。藤蔓解锁按棋盘分组，每个时间点直接保存坐标，例如 `"主棋盘": {"10秒": {"行": 5, "列": 3}}`；不再单独导出行、列时间线或物品信息。等级奖励记录当时实际领取的物品名称和数量，旧记录缺失时明确显示未记录，不使用当前配置猜测。缺失的旧指标不虚构为 0。原始演算 JSON/JSON.GZ 仍用于页面加载及内部校验；精简记录用于查看和数据分析。

## 各产线生产器折合一级份数

逐条按 `data/lines.json` 中的生产器链统计，按一级份数折算后相加：1 级计 1、2 级计 2、3 级计 4、4 级计 8，以此类推，公式为 `2^(等级-1)`。例如 2 级篮子 + 3 级篮子 = 食物产线 6 份。包含 1、2 级尚不能生产的部件；范围是已解锁棋盘、储物洞和暂存区，锁定/覆盖格以及未购买气泡不计入。物品在这三个位置之间转移不改变总份数。

每次事件快照与轮次结束快照分别保存 `gen_total_<产线ID>` 数值，变化量跟随原事件记录；报表 `production_lines` 保存名称、生产器链和指标键。报表 `production_counting: "level1_equivalent"` 标明新口径。两件同级物品合成后总份数保持不变。页面分别展示每条产线的本轮最终总份数、历史曲线和所选事件时刻的数值。旧记录使用原等级和时明确标为旧口径；未采集此指标时显示未记录，不推算成零。

完整事件记录保留动作、时间、状态、变化量和动作详情，不保存或显示原因字段。

## 新增观察指标

- 藤蔓解锁：主棋盘和月石棋盘从锁定状态变为解锁时，单独记录 `unlock` 事件，含棋盘、格子行列、物品、合成结果及关联 `merge_seq`。与触发合成同一时间，不额外推进时间；默认重要事件视图可见。揭开巨石而露出藤蔓不算藤蔓解锁。
- 订单颜色：按订单实际 `detail.rw.xp > 0` 判定，带经验为黄色，无经验为蓝色，与主线/副线标记无关。
- 琥珀、沙漏：`gems` / `sand` 为当前持有量；`amber_earned` / `sand_earned` 为本轮累计到账量，不含初始资源及未领取实物。监听每次货币变化，消耗不减少累计值，同一动作内先花后领仍计入完整收入。每轮 `resource_initial` 保存初始余额。
- 生产器最高等级：各产线新增 `gen_max_<产线ID>`，与折合份数使用同一持有范围。未拥有为 0，未采集的旧记录显示未记录。汇总卡、曲线和事件状态均可查看。

## 决策顺序

贝币足够就独立升级部落 → 可领奖励 → 教学完成检查 → 已完成目标订单 / 制作料理 → 选择主线或副线目标 → 取回储物洞材料 → 合成与揭开覆盖 → 活动合成及领奖 → 按产物概率选择生产器 → 存储 / 删除 → 等待资源或计时事件。

新手阶段使用初始教学订单与引导提供的草籽订单，跳过界面指引和动画。所有生产、合成、开箱、交单、建造、活动消耗与奖励使用本地正式规则；未解锁卡包保留，不能跳过解锁条件。副线完成不了时会记录阻塞而非增加资源。

作息模型：只在 `schedule` 的在线时段操作，时段外快进（`offline` 事件，体力照常恢复、满了就浪费）；在线时空等太久提前下线（`stuck` 事件，体力为 0 时另计「卡体力」）。

虚拟时钟会推进体力恢复、生产器冷却、料理、气泡过期、跨日免费补给与对手成绩。模拟不付费、不看广告；不使用付费 UFO、额外买体力或通行证会员。对手使用当前试玩版的模拟曲线。该策略可复现，但不保证最优，也不等同于真人游玩耗时。原始配置奖励很充足时，连续自动操作会显著快于真人。

## 验证

```bash
python tools/sim/check.py /path/to/report.json
python tools/sim/check.py /path/to/report-a.json /path/to/report-b.json
```

第二种用法要求相同配置和种子，比较两次完整事件流的决定、资源和进度（排除不影响规则的气泡 UID）。测试用 `max_actions` 可缩短验证时间。普通局部测试另见 `tools/check_duel.gd`、`tools/check_card_unlock.gd`、`tools/check_merge_event.gd`。
